# Установка Korkovts v10 Research

## Что загрузить в GitHub

В корень репозитория `Korkovts` загрузи с заменой:

- всю папку `app`
- `requirements.txt`
- `README.md`
- `RESEARCH_V10_RU.md`

Файлы Python должны остаться внутри `app`: например `app/bot.py`,
`app/liquidations.py`, `app/research.py` и `app/strategy.py`.

## Railway

Сохрани существующий Railway Volume с mount path `/data` и переменные:

```text
DATABASE_PATH=/data/signals.db
AUTO_SCAN_INTERVAL_MIN=10
SIGNAL_COOLDOWN_HOURS=24
MIN_SIGNAL_SCORE=82
MAX_SYMBOLS_TO_SCAN=0
DEEP_ANALYSIS_LIMIT=0
SCAN_CONCURRENCY=6
ROUND_TRIP_COST_PCT=0.12
```

Команда запуска остаётся:

```text
python -m app.bot
```

После `Deployment successful`:

1. Отправь боту `/start`.
2. Открой `/system`: должно быть `KORKOVTS V10R`, ADL BTC, ширина рынка и
   статус потока ликвидаций.
3. Потоку ликвидаций требуется 5 минут прогрева. Его отсутствие не создаёт
   сигнал и не угадывает направление.
4. Открой `/lab`: в начале там будет нулевая когорта.
5. Строка `Теневой контроль` растёт только тогда, когда ADL или ширина рынка
   действительно отсекает в остальном подходящий кандидат. Такие записи не
   являются сигналами и в Telegram не приходят.

После первого полного скана `/system` покажет кэш закрытых свечей. Он живёт
только до следующего закрытия соответствующего таймфрейма и снижает нагрузку на
Binance; очищать его вручную не нужно.

## Правила теста

- Первые 100 активированных и закрытых сигналов — только наблюдение или
  бумажный учёт.
- Не меняй пороги после нескольких убытков: иначе выборка потеряет смысл.
- Сравнивай `1H` и `15M`, LONG и SHORT, а также оба сценария отдельно.
- Не считай несколько сигналов из одного корреляционного кластера независимыми
  сделками.
- Риск на одну бумажную сделку: 0,25–0,5%; плечо выше указанного ботом не
  использовать.

v10 Research не обещает прибыль. Её задача — собрать чистые будущие данные и
проверить, улучшают ли новые независимые фильтры результат после издержек.
